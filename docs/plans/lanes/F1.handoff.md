# Lane F1 handoff — Federation base

**Status:** implementation in progress; verification and gates pending · **Updated:** 2026-10-21
**Branch:** `lane/f1-federation` · **Base/main:** `cf52c4b`

## Authorized plan and boundary

Implement ADR-0018's federation base as an opt-in kernel service: signed node credentials,
device authorization, scoped log replication, HLC/remove-wins configuration, provenance
telemetry and version-bound commands. Use K2's read/egress boundary and R1's home transaction;
do not create competing session or run writers. Keep the application loopback-only by default.

The plan was autonomous under the owner's explicit request. The principal risks were
arrival-order-dependent merges, concurrent revocation, stale commands, replica write admission,
secret/reasoning egress, protocol downgrade and K4 migration collisions. Mitigations are signed
origin operations, causal remove-wins frontiers, atomic version/effect/receipt checks, explicit
home pins, strict export/import scopes and independently tracked additive migration 34.
Rollback preserves federation tables when disabled; a stopped pre-upgrade SQLite/WAL backup is
the schema rollback. No third-party code/dependency was copied or added.

The primary verification is deterministic in-process simulation: partitions, delay, reordering,
duplication and skew. Each exit item has a direct assertion. Targeted tests precede full
regression gates. Independent fresh-context review checks convergence, fencing, trust and
versioning; its fixes will be separate commits. The integrator performs Claude cross-family
review and live Linux/network validation separately.
