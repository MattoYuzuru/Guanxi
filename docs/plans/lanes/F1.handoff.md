## Outcome and boundary

F1 provides an opt-in `guanxi.federation` kernel plugin (`federation.base`) and the strict
`@guanxi/contract/federation` Zod contract. It adds device authorization/public-key node
credentials, signed replay-protected requests, HLC/remove-wins shared configuration,
provenance telemetry, scoped read-only session/run replicas and version-bound home commands.
The signed channel uses a host-injected transport and independent peer synchronization;
there is no required hub. Defaults install no federation plugin, tables or routes.

The [module API/storage guide](../../../packages/server/src/federation/README.md) documents
activation, host approval/pinning, request proofs, schemas, synchronization and recovery.
[Network guidance](../../architecture/FEDERATION_NETWORK.md) records Tailscale first,
Headscale as the alternative, the Fedora PC home, interactive MacBook/Fedora laptop and
relay-only `keykomi`. The application listener stays loopback by default. Exposing the
legacy application listener is not a federation deployment strategy.

Initial delivery used local in-process HTTP, injected clocks/transports and temporary/in-memory
SQLite databases. Review 1 additionally ran authorized validation through `ssh asus` in a
temporary bundle-created clone, with `nice -n 10`. No VPN/SSH configuration, installed model,
owner keychain, vendor login or real user database is changed. The regression envelope also
includes existing loopback fixture tests, an owned native execution sandbox and mocked browsers.
The current fixes and evidence are in [Review 1 fixes](#review-1-fixes); earlier review and gate
records below are historical baselines.

## Plan, storage and authority defaults

The autonomous plan under the owner's explicit request was contract → additive persistence →
kernel service/routes/channel → K2/R1 integration → deterministic simulation → independent
review → gates/handoff. The risks were arrival-order-dependent merges, concurrent revocation,
stale commands, replica writer admission, private-data egress, downgrade and K4 collisions.
No third-party source or dependency was added; existing Node/Hono/Zod/K1/K2/R1 APIs are reused.

Migration **34** is independently tracked by `federation_migrations` on the node database.
It leaves the main migration array, `PRAGMA user_version` and reserved K4 slots **32–33**
untouched. Its ledger and DDL are transactional; tests assert rollback/retry, preserved old
settings, a single ledger row and reopen behavior. No down migration or destructive backfill
exists. Disable federation to retain data while removing the service/routes. Prefer a forward
fix; schema rollback uses the stopped pre-upgrade SQLite/WAL backup.

Explicit conservative implementation defaults:

- Peers and stream home/epoch pins require host approval; gossip never assigns a writer.
- Causal vectors contain only unbroken actually stored prefixes, isolated by account. No
  origin can attest missing history on another's behalf. Missing context defers an ingest;
  independent admissible operations commit separately.
- Local counters derive from locally signed stored operations. Invented missing local history
  never enters the op-log or clock; local writes remain available.
- No vault replication API exists, including for owner devices. Vendor OAuth tokens never
  enter this channel. Encrypted owner-device vault synchronization needs its own opt-in key
  exchange. Connection metadata stays owner-bound (D-190).
- Prompt commands become durable K2 input plus an ordered inbox; they do not start a model.
  K4 must consume/acknowledge that inbox through its executor policy.

**H1/H4 dependency rule:** a skipped author's missing history is never implicitly observed.
A dependent operation, including a revoke and later same-origin successors, stays deferred.
Anti-entropy retries it but does not keep an unbounded local deferred queue. If that history will
never be admitted, retry cannot repair it: a current admin must reauthor the intended change
from an admissible receiver history, or an operator must review a rebaseline. P4/P4b assert an
independent operation commits and a locally reauthored revoke takes effect on both nodes.
This trades dependent-update availability for causal safety; a dependent revoke is not claimed
as automatically propagated.

### Remaining named Low residuals

- **F1-L-HANDSHAKE:** handshake responses are unsigned; transport authenticity/TLS is required.
  An attacker able to edit responses can force read-only mode or denial of service.
- **F1-L-HLC-HOPS:** HLC drift can compound across hops, causing transient rejection until
