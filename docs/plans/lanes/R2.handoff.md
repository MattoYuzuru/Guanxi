## Outcome

`guanxi.relay` provides `agent.relay`, loaded after K3 by the server. The trusted host supplies
an R1 attempt, immutable planner revision, delegation caps, sandboxed workspace and actual
runtime window/token meter. Loading starts no inference. This slice adds no HTTP or UI flow.
The [service README](../../../packages/server/src/relay/README.md) describes admission,
recovery, schema, tooling and remaining integrations.

- Reserve-derived thresholds and a final scrubbed-request ceiling protect every work,
  probe and fresh narrative call, including final K3 scrubbing. Local `prompt_eval_count` mismatch/length is a protocol error.
- Run-scoped immutable plans, derived gate/item states, paged `work.query`, typed append-only
  notes and deterministic note selection preserve authoritative task state. Amendments remain
  proposals for the lead (D-158). Selected notes survive into the next work context.
- `guanxi.handoff/v1` references the complete immutable boundary ledger by SHA-256, with a
  bounded strip, selected notes and narrative. JSON and Markdown each fit within 15% of W.
  Accumulated evidence stays queryable without growing the injected context.
- Seal JSON, Markdown, artifact digest, ledger snapshot and git bundle upload atomically
  to the R1 home in the same fenced transaction as the K2 event. Old tokens cannot seal or
  become current last-sealed. Restart recovery requires a new R1 attempt and never resumes
  pending inference/tools automatically.
- Critical integrity/probe failures rebuild a degraded handoff and retry once; another
  failure requests J2 and escalates. Failed narrative preserves harness-observed progress.
  Notes/proposals/verification requests are not progress; two empty cycles request J2,
  three escalate. Brief caps stop new work in `wrapping_up` with a ledger report.
- K3 dispatch observations acknowledge wakes before responses finish, after local governor
  admission and version preflight. Rejected observations abort and consume the response.
- K4 ExecutionOwner tools protect planner tests/specs/CI and `.git`. Raw git object plumbing
  avoids hooks, clean/process/smudge filters and archive attributes. Gates materialize an
  isolated committed tree, restore planner-protected bytes, reject linked/gitlink trees,
  and recheck all acceptance at final HEAD. Changed HEAD invalidates earlier done evidence.
  Cleanup uncertainty stops before another checkpoint and retains its quarantined tree.

## Limits and next slice

- Runtime admission needs a trusted actual-window observation and rendered-request counter.
  K3 does not yet supply a universal live meter; no catalog/requested-window substitution
  is made. The fixture path is locally validated; live-model task quality is not.
- The host must assign an isolated worktree and immutable K4 policy. Linked/gitlink base or
  candidate trees fail closed. External filesystem writers are outside ownership guarantees.
- This is internal run mode, not `packages/work` extraction, project boards, tracker sync,
  a public relay API or a UI/CLI workflow.
- R3 owns judge execution/verdicts, ETA and delegation policy. B3 owns the real 32k relay
  quality/non-inferiority benchmark. R2 emits judge requests and escalations, without claiming
  completed judge reviews or unlimited model quality.
- Seals live in the single-node home database. F1 integration of cross-node artifact transport,
  power/handover and universal resource ownership remains separate. R1/K4/K3 named residuals
  remain as recorded in their evidence; R2 does not promote those stages wholesale.

Next: integrator Claude cross-family review of this branch and its hand-off, then integration
of a concrete runtime meter/host admission and R3 per the roadmap. Do not restart unsafe work
automatically or accept executor plan proposals as lead decisions.
