Paste everything below the line into a Codex session in the lane worktree.

You are implementing part U1-a (workspace layout engine and modes) of stage U1 of Guanxi, an
Apache-2.0, local-first agent harness. `main` has K1–K4, R1, DS1-a and DS1-b. DS1-c (the ESLint
and stylelint rules G8 and G9, the suppression ratchet and the colour codemod) is in its final
review on branch `lane/ds1-c-ratchet`. Write your code to DS1-c's rules from the start: read its
`eslint.config.mjs` and `packages/ui/gates/lint/` on that branch. Merge `main` once DS1-c lands
there.

Read first, in order:

1. `AGENTS.md`, `docs/plans/lanes/README.md` and `docs/plans/WORKFLOW.md`.
2. `docs/plans/ROADMAP.md` §U1, `docs/decisions/0036-workspace-layout-and-experience-modes.md`
   and `docs/design/LAYOUT_AND_SCREENS.md`.
3. `.agents/skills/guanxi-ui/SKILL.md`, then `docs/design/FOUNDATIONS.md`,
   `COMPONENTS_AND_CATALOG.md`, `PRINCIPLES.md` and `BRAND.md`.
4. `packages/ui` (components and catalog), `packages/kernel/README.md` (slots), and the current
   `packages/web/src/App.tsx` and router.

Scope (ADR-0036 §1–7):

- **Engine.** `dockview-core` and `dockview-react`, MIT, pinned exactly, behind a thin
  `WorkspaceLayout` adapter. Only the adapter may import Dockview. Never import
  `dockview-enterprise`; add it to the licence deny list.
- **Zones.** Left, right, top, bottom, centre grid, floating and popout. Popout works through a
  same-origin popout page.
- **Blocks.** The keyed kernel slot `workspace.block` with the `BlockContribution` contract.
  Built-in block shells: Context, Changes, Plan, Processes, Environment, Files, Terminal,
  Artifacts, a Browser placeholder and Sub-agents. Each is a minimal real pane or a truthful
  empty state, never fake data. Unloading a plugin turns its blocks into placeholders.
- **Accessibility.**
  - "Move block to…" from the block menu, the command entry point and the keyboard.
  - F6 and Shift+F6 cycle zones.
  - Every move is announced in a live region.
  - Drag previews respect reduced motion.
- **Layout documents.** `guanxi.layout/1`, validated with Zod in `packages/contract`:
  - resolution order: device, then project + mode, then account + mode, then built-in;
  - named layouts per scope;
  - device-local popout and float geometry;
  - last-writer-wins by `(rev, updatedAt, device)`, keeping the losing copy as
    "Recovered layout";
  - unknown blocks become placeholders;
  - an engine major-version mismatch falls back to the built-in layout;
  - safe mode ignores plugin blocks;
  - no secret values in `params`.

  Persistence goes through the node (REST in the contract, with server route, web client and
  tests).
- **Modes.** Developer and Visual each keep their own active layout; switching never deletes
  the other. Use the defaults from LAYOUT_AND_SCREENS §4–5.
- **Density.** Density presets are token sets and never move blocks.
- **Phone.** No docking: blocks become a stacked tab list ordered by priority.
- **Session workspace.** Dock lanes and the composer, with the existing chat as the centre
  block.

Out of scope for U1-a, left to U1-b and U1-c: the navigation sidebar, status strip, command
palette, new-session screen, side chats, glossary, and migrating old pages.

**Exit gate.** Each item needs an assertion that fails when the property is violated.

- ADR-0036 spike criteria 1, 2, 4 and 5:
  - zones from locked groups using free APIs only;
  - keyboard "Move block to…" without dragging, announced (assert the live-region text);
  - Terminal and Browser blocks keep their state across move, float and popout;
  - a 30-block layout restores within a stated budget (assert it).
- Criterion 3 (popout in a sandboxed Electron renderer) cannot be tested before U2. Prove the
  same-origin popout page in Chromium and name the Electron part as a residual.
- Layouts resolve in the documented order and survive a mode switch, shown by golden tests.
- Last-writer-wins keeps the loser as "Recovered layout" (count assertion).
- Browser tests cover keyboard move, F6 cycling, reduced motion, a 390 px phone layout, and both
  themes and both densities.

**Rules:**

- Run `npm ci` first.
- Export `GUANXI_WEB_PORT=5199 GUANXI_API_PORT=4399 GUANXI_DATA_DIR="$PWD/.lane-data"`.
- Run typecheck, lint:md, check:licenses and ui:check directly.
- Run npm test, test:web:browser, ui:check:browser and build one at a time through
  `agent-dev run --cwd "$PWD" --node 26 --resource heavy --lock-timeout 3600 -- <command>`.
- New components go through the `@guanxi/ui` catalog lifecycle as `draft` or `review`. Never
  write `approved`, and never edit `packages/ui/src` components that already have a review
  record. User-facing strings go through locale keys (English source, curated Russian).
- No live models and no network in tests.

**Independent verification:** run a fresh-context self-review of the whole diff, covering
accessibility, layout-document validation, replication, licensing and adapter isolation. Put
the fixes in separate commits. The integrator then arranges a Claude cross-family review.

Finish with `docs/plans/lanes/U1a.handoff.md`. Commit on `lane/u1a-workspace` only, and do not
push.
