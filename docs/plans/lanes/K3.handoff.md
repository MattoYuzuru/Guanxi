# K3 — Model access handoff

**Status:** implemented consumer layer, locally validated; upstream full-gate blocker and K2 integration pending · **Updated:** 2026-10-20

**Branch:** `lane/k3-model-access` · **Initial base:** `4588ce6` · **Merged main:** `aec54fd`

## Delivered

- Persistent account-scoped connection registry for sanctioned CLI agents, model APIs,
  this-node Ollama and search/STT services; Zod wire schemas and provenance-bearing facts.
- AES-256-GCM vault with an OS-keychain-wrapped account data key, opaque `secret://` refs,
  JIT dispatch and explicit interactive locking. Unattended defaults false and requires
  immutable owner-device/node-key opt-in. Lock/unload invalidate pending keychain work.
- Exact-pinned MIT `@earendil-works/pi-ai` 1.3.0 integration. Login/provider factories are
  excluded; Anthropic OAuth token families are refused across providers before dispatch.
  Google uses its supported native SDK transport. K1's Ollama adapter and governor are reused.
- OpenRouter key-allowance and DeepSeek account-balance probes with recorded documentation
  response fixtures; timestamp/source/confidence and an append-only per-connection usage ledger.
- Two pinned models.dev records as independent metadata evidence, with MIT attribution/license.
- Connections in Settings, loaded when opened: create, unlock/lock, save-key-without-readback,
  unattended state, balance refresh, provenance and usage. English source/curated Russian,
  selected-locale numbers/dates, loading/empty/error/offline/unknown states and keyboard controls.
- Artifact construction scrubs before writing/hashing; exclusive 0600 file creation. Callers
  provide an already authorized destination; there is no arbitrary-path HTTP endpoint.

The current-state module guide is
[`packages/server/src/connections/README.md`](../../../packages/server/src/connections/README.md).
Legacy Chat/search are not rerouted by K3. K4 consumes this model boundary; K5 executes the
registered official subscription CLIs. No proprietary CLI or SDK was bundled.

   The last full green run and the post-merge core diagnostic are separately recorded above.
2. **K2 integration is required before production use.** The unmerged K2 interface was checked
   against its published `egress/types.ts`/README. The current production bridge deliberately
   throws on scrub, while tests use an isolated minimal matcher. Merge K2 into main, merge that
   main into this lane, delete the bridge/copied interface, import/load K2's provider, switch
   these tests to the real provider, and rerun the trace and all gates. Event/export guarantees
   belong to K2 and are not claimed by K3's consumer fixture.
3. Run the integrator's Claude cross-family review; fix any confirmed findings in separate
   commits. Then merge this lane through the normal integrator protocol. Nothing was pushed.
4. macOS/Windows keyring code is wired but the owner's OS store was never touched. Linux vault
   activation is refused because current native keyring binaries statically link libdbus under
   AFL/GPL terms outside ADR-0016. An approved backend and native packaging license review are
   required before Linux distribution; npm's SPDX metadata gate does not prove that property.
5. Google SDK transport cannot accept the custom redirect-rejecting fetch wrapper. It receives
   the fixed catalog endpoint, explicit key and abort signal; the limitation is documented and
   its normal/cancelled requests are fixture-tested.
6. Current HTTP account scope is the local owner. Remote accounts/authentication, vault
   replication/grants, admin usage APIs, CLI execution, service execution, durable request
   idempotency and invoice reconciliation remain their later stages. This lane does not turn
   legacy Chat into a K4 native agent. The models.dev seed contains two records, not a mirror.
