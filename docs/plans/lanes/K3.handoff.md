# K3 — Model access handoff

**Status:** implementation in progress · **Base:** `4588ce6` · **Branch:** `lane/k3-model-access`

## Implementation plan

Authorized by the K3 lane request. Build a persistent per-account connection registry and
append-only cost ledger, encrypted vault, provider and local-runtime kernel services, recorded
balance probes and a Connections section in Settings. Keep subscription CLI execution for K5;
K3 records sanctioned routes and billing provenance. Search and STT are service roles.

The vault stores only authenticated ciphertext in its own SQLite database; a random data key
is wrapped by an OS-keychain key. An unlocked interactive session is required by default;
background access requires the connection's explicit unattended flag and owner-device opt-in.
Scrub at model construction and before artifact hashing/writing; never import OAuth modules
or permit an Anthropic OAuth credential. No provider calls or owner's keychain in tests.

Use pi-ai (MIT, exact dependency), models.dev metadata (MIT, attributed if copied), the K1
Ollama kernel adapter and the documented K2 `egress.scrubber` service. A temporary local exact
match implementation bridges K2 until its merge. No legacy settings or data migration.
Rollback disables the K3 plugins/routes; retain the separate database and keychain entry.

Risks to test: ciphertext tampering/account isolation, restart and locked-session access,
concurrent/idempotent ledger writes, denied auth paths, cancellation and plugin unload,
provider errors leaking credentials, timestamp-free facts and UI retry/offline states.

Validation: typecheck, lint:md and licenses directly; npm test, browser gate and build one at
a time through agent-dev Node 26 with resource heavy, ports 5187/4387 and isolated .lane-data.
Exit-gate tests explicitly assert secret absence, unknown balances without timestamps,
each recorded probe fixture, denied Anthropic OAuth and unattended off by default.
