## Outcome

IX0 literal Node search, IX1 WASM tree-sitter repository maps and IX2 SQLite FTS5 trigram
indexing are implemented through `project.index`. Native projects register their roots
automatically. Tools are `search` and `repo.map` (provider-safe alias `repo_map`), with
current/indexed commit, age, observation and coverage. The complete map JSON has a stated
UTF-8-byte token upper bound. IX3 has no implementation, model loader or provider call;
the future flag is inert even when true. No ripgrep binary or Serena is bundled.

See the [index README](../../../packages/server/src/indexing/README.md) for settings,
source licenses, lifecycle, freshness scope and recovery. The default IX2 threshold is
1000 eligible text files, configurable through `start({ indexSettings })` or plugin config.
The per-file safety policy (2 MiB) and refresh interval (5 s) are documented settings.

Data lives only in `<dataDir>/knowledge-index/index.sqlite`, sidecar schema v1. There is
**no shared node migration**, so no migration-number collision with F1/R2/K5. Remove the
sidecar with the node stopped to rebuild; project roots and session policies are unchanged.
Captured worker sources and temporary runtime files remain in the data directory and are
removed on service close. Builds use preemptible process-local idle governor leases;
interactive admission never waits for index cleanup. D-189 headroom observations carry
source/time/confidence, and shrinking headroom cancels the owner.

## Residual boundaries and shared edits

- macOS scanner containment and synthetic LSP protocol paths are locally exercised. Linux
  sandbox source was reviewed and hardened, but not executed on this Mac-only task. Windows
  fails closed. No remote-host, production or installed real language-server validation is
  claimed. The server must exist inside ExecutionOwner; a host-only macOS server can fall
  back to the cached map. No GPL/proprietary implementation is bundled.
- Freshness is a filesystem snapshot, not an atomic view against external concurrent edits.
  The scanner hashes eligible bytes per query: content and parsing are shared/incremental;
  no measured localisation speedup or O(1) freshness claim is made.
- Forced process death cannot execute final cleanup. A later successful build purges newly
  registered secrets. Previously legitimate content can remain in SQLite WAL/free pages
  until reclaimed; forensic erasure is not claimed. Git metadata, runtime/dependency and
  explicit system-library reads are required sandbox exceptions.
- Idle build state is process-local and retryable, not an R1 durable inference run or a fleet
  lease. Automatic relocation/placement remains fleet work.
- K4's existing output artifact/retention and sandbox residuals remain. X1 adds no UI, wire
  contract fields, main database migration or model lifecycle operation.
