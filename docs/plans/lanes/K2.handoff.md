## Outcome

One append-only event log per session is now the trace
([ADR-0023](../../decisions/0023-session-event-log-and-tracing.md)). It runs as kernel plugins
on `@guanxi/kernel` (ADR-0037):

- **`guanxi.egress-scrubber`** provides `egress.scrubber`. It does exact-match redaction of
  registered secret values (raw, JSON-escaped and URI-encoded forms) and has a readiness gate
  for secret sources. The stable interface for K3 is
  [`egress/types.ts`](../../../packages/server/src/egress/types.ts), with semantics in
  [`egress/README.md`](../../../packages/server/src/egress/README.md).
- **`guanxi.session-log`** provides `session.log`.
  - It uses migration 29 (`sessions`, `session_writers`, `session_events`, an FTS5 index).
  - There is one writer per session (D-116): one `SessionHandle` per process, plus a writer
    epoch that the database enforces.
  - Each append is a single transaction and is idempotent by key or expected `seq`.
  - Payloads are scrubbed at write and again at read.
  - Reasoning is its own class, with retention. Remote agents never receive it, and exports
    never contain it (D-113).
  - The guarantees, and the test that proves each, are in
    [`session-log/README.md`](../../../packages/server/src/session-log/README.md).
- **Legacy port:** `JobStore` appends the Chat trace inside its own transactions through
  `ChatSessionMirror`.
  - Token and thinking deltas are aggregated from `job_events` at the next non-delta Job event,
    so the scrubber sees whole messages and nothing is held in memory.
  - This is a strangler mirror, not a full port. `job_events` stays the execution substrate
    until R1.
- **Interim inspector:**
  - web route `/inspector[/:sessionId]` with a timeline, spans, FTS5 search, a token meter and
    an export without reasoning;
  - `/api/sessions/**` routes, plus a "Trace" tab and a chat header link;
  - the agent query tool `session_log_query` with `audienceForAgent`.

## Cross-lane: K3 (egress.scrubber)

- **Interface:** first committed at `d30eb7e`; `register`, `unregister` and `scrub` have not
  changed since.
- **Readiness (K3 review H3):** added at `b9aac06`. The new methods are `expect`, `ready`,
  `isReady`, `pendingSources` and `whenReady`, plus `EgressScrubberConfig.expectedSources`.
  - **K3 must add `'vault'` to the scrubber row's config** in `LEGACY_SERVER_PROFILE`
    (`packages/server/src/runtime/kernel.ts`), then call `ready('vault')` after registering. An

- **Session-log behaviour while the scrubber is not ready:**
  - the mirror buffers in memory (bounded to 1,000 writes and 8 MiB);
  - on overflow it refuses the write with `egress_buffer_full` and the Job rolls back;
  - handles, reads, routes, export and the query tool fail closed with `egress_not_ready`
    (HTTP 503, `details.pendingSources`).
- **Fail-closed stub:** updated in the egress README. The notes folder has a hand-over note.
- **`app.ts`:** K2 adds only `server.route('/api/sessions', …)`. K3's Host-allowlist middleware

## Residual risk (deferred, with the stage that owns it)

- **Legacy tables (R1).** `job_events.output` and `messages` keep unscrubbed private Chat
  payloads. The trace, inspector, exports and the query tool never read them; K3 scrubs model
  requests.
- **Registrant ownership (P1, before the plugin-API freeze).** Any in-process plugin that
  `requires` `egress.scrubber` can `unregister` another's ref (architecture M2). T0/T1 plugins
  are trusted; T2 runs out of process.
- **`session.log` surface (K4).** The service is the raw `SessionLog` instance, with no frozen
  facade and no node-bound audience (architecture M3).
- **Sessions written by the mirror (K4).** Once the mirror has written a session, `open()`
  refuses it for the life of the process (architecture M5).
- **Data-directory lock (R1).** It replaces the PID liveness heuristic. Until then, PID reuse
  delays a handover by up to 30 s, and startup recovery fails in that window (architecture
  H2(b)).
- **Trace failures (decision recorded).** A refused trace write rolls back the Chat Job write.
  This is deliberate fail-closed behaviour (architecture H2(c)).
- **Held-back writes.** If the process exits before the scrubber becomes ready, the held-back
  writes are lost; they are never written unscrubbed.
- **Not built (later stages):**
  - backfill of sessions from before migration 29;
  - artifacts for large payloads, and bounded tool arguments and results (K4);
  - per-project reasoning retention;
  - OTel export;
  - parsing of inline `<think>` text (K3);
  - query-tool tail/limit semantics (K4);
  - retention for agent sessions;
  - tombstones for replication (F1).
- **Remote audiences** see `seq` gaps where reasoning events are, which reveals their count but
  not their content.
- **Not verified in this lane:** a real screen reader; forced-colours rendering of search marks
  in a real browser; the legacy primitives' borders below 3:1 contrast; route-change focus
  across the app. Accessibility L6, L10 and L12 belong to the legacy UI, which DS1-c/U1 replace.
