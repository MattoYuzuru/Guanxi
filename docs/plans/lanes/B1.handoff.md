## Outcome and limits

`@guanxi/bench` supplies a measurement protocol, task metadata selection, statistical reducers,
budget reservations, private JSON/standalone HTML reports, an optional kernel plugin and a
managed external Harbor process. The Mac path needs no host. The Fedora path exercised the
real pinned Harbor and mini-swe-agent with two offline toy tasks under the dedicated user.
It adds no native-agent scaffolding, REST contract, migration or app UI.

**This is not the full B1 exit.** The stock worker deliberately refuses real A/B and noise-floor
execution. It does not stage or verify the immutable 50 fresh SWE-rebench + 30 Verified task
contents. Its metadata selector and recorded-results analyzer support that protocol, but
metadata is not execution evidence. The five-seed noise-floor procedure is implemented and
fixture-tested; no real model noise floor has been measured.

The `GuanxiExec` adapter validates K4 stdout inside a prepared task container. It is tested
against a fake container boundary, not a real native-agent benchmark image. Such images and
their isolated node/project/connection setup are unfinished. K4 stdout has no token/cost usage;
unknown usage stays unknown. There is no shipped K3 gateway that quotes and reserves each
provider request before billing. All stock paid execution is refused, including after an
approval, until a genuinely bounded executor exists. No paid run was started.

See [package documentation](../../../packages/bench/README.md) for interfaces, commands and
failure semantics. The integrator must keep B1 open and must not activate ADR-0025 as an
operational evolution gate on this foundation alone.

## Implementation

- External Python 3.12.14, Harbor 0.24.0 and mini-swe-agent 2.4.6; frozen `uv.lock`, no extras,
  no bundled interpreter or system-wide install. Environments live in `.lane-data/bench-python`
  and `/home/guanxi-bench/b1/.venv`.
- Per-task seed averages, task-cluster paired bootstrap (10,000 replicates), exact two-sided
  McNemar on all-seed task success, Holm p-values, family-adjusted bootstrap intervals,
  pass^k and strict −5-point non-inferiority / superiority / 15% savings margins.
  Results are fixed-horizon `measurement_only`, requiring holdout and guardrails.
- Complete tuple validation, paired exclusion of infrastructure-tainted tasks, separate
  infra/failure counts, explicit unknown billing and escaped standalone HTML. Archived
  analysis remains usable after its corpus ages; launch freshness still applies.
- Transactional SQLite reservation of the whole worst case before dispatch: per-arm cap,
  protected $200 monthly cap and provider/day tokens. Holds survive crash, invalid results
  and restart; successful holds are conservatively retained too. Duplicate IDs cannot
  dispatch again. Metered execution cannot straddle a UTC budget day/month.
- Optional `bench.runner` plugin consumes `runs.durable` and `egress.scrubber`; cancellation,
  lease loss and unload stop the child. Unconfirmed remote cleanup is not called successful
  cancellation. The server does not load this plugin by default.
- Configurable SSH host/root, neutral `/tmp`, `sudo -n -u guanxi-bench env -i`, explicit venv.
  Rootless/systemd/UID preflight; observed `user-1001.slice`; container UID/GID 65532;
  CPU/memory/PID limits; no network, GPU, host binds or capabilities. Each stdout/stderr
  pipe is bounded to 1 MiB. Exact container IDs are removed and absence checked.
