## Outcome

`guanxi.durable-runs` provides `runs.durable` through the own kernel, depending on K2's
`session.log` and `egress.scrubber`. Its service exposes the run store and scheduler health.
The [implementation README](../../../packages/server/src/runs/README.md) documents the exact
API, restart table, resource ownership, clock/grace defaults and migration recovery.

- Additive migrations **30 and 31** add runs, attempts, fenced leases, promises, timers, the
  wake outbox, retained resources and a per-run cost ledger. Migration 31 persists the prior
  home's regrant safety bound. All migrations 1–29, and migration 30 during review, remain
  byte-identical; digests pin all of them.
- Run states include `waiting_children`, `input_required`, `wrapping_up` and
  `interrupted`, with the ADR-0019 A2A mapping.
- Delegation, hibernation, resolution, signals, cancellation, wake creation and their K2
  `run.lifecycle` events commit transactionally. Notifications happen after commit.
- Wake preparation and first-model-call acknowledgment are distinct. Interrupted,
  unacknowledged deliveries get fresh fenced attempts; acknowledged wakes do not redeliver.
- Deadlines use first-commit-wins resolution, with explicit cancel-after-report/detach
  policies. Cancellation follows the delegation chain once.
- Worktree/scratch retention belongs to a run and survives released execution leases.
  Costs deduplicate observations and keep unknown monetary amounts and currencies distinct.
- The existing inspector renders the additive event with locale keys and exact overlap/reload
  count coverage. No component, design approval or visual style was created or changed.
- Legacy Chat Jobs retain their compatible state machine and replay. No unsafe inference is
  backfilled or automatically replayed. This is a durable orchestration service for K4/R2,
  not a claim that a live lead/model executor has been implemented.

## Shared edits and residual boundaries

R1-authored shared edits are:

- `store/db.ts`: append migration entries only;
- `runtime/kernel.ts`: load/pin the durable-runs service when the node DB is present;
- `contract/src/events/session-events.ts`: additive run state/mapping and event schema;
- inspector type label/detail, locale keys and its one regression test;
- existing migration test version expectations, downgrade/snapshot fixtures and boot counts;
- ADR-0019's implementation boundary and the legacy runtime lifecycle extension.

No dependency or third-party code was added by R1. K3's package/lock/license changes came only
from main. No R1 edits were authored in PHASE_STATUS or NEXT_AGENT_PROMPT; changes there came
from main merges. No design component approval status changed.

Limits and follow-ups:

- K4/R2 must attach the actual executor, honor report-only `wrapping_up`, renew/check fences
  at effects, and call `modelStarted` only after a model call starts. R1 never invokes a model.
  Full wake packets/handoff artifacts, external lead protocols, unavailable-lead fallback and
  provider billing validation remain later integration work.
- Delegation requires an explicit always-on home assertion; default server boot refuses it.
  Power assertions, home handover, remote grace and backup-restore epoch changes belong to F1
  and ADR-0038 integration.
- Unclean home recovery can wait up to 91 seconds with defaults; startup returns
  `writer_busy` until the persisted bound. This is a durable execution-home lease, not an OS
  data-directory lock or a replacement of every legacy writer mechanism.
- Resource owners retain/delete actual worktrees using the returned opaque keys. R1's reaper
  releases eligible ownership and never deletes a host path itself.
- K2's legacy raw Job payload, historical backfill and operator catch-up repair limitations
  remain; R1 does not claim a complete Chat execution port.
