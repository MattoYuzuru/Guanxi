## Outcome

The Cordis spike was rejected by the owner (D-183). `@guanxi/kernel` is now Guanxi's own plugin
kernel ([ADR-0037](../../decisions/0037-own-plugin-kernel.md)), about 1.8k lines with no
runtime dependency. `cordis` and `@cordisjs/plugin-loader` are gone from every `package.json`
and the lockfile, and `boundary.test.ts` fails if either comes back.

What it keeps from Cordis:

- a plugin tree with child plugins;
- services with `requires` and optional `uses`;
- revertible effects;
- events;
- profiles built from patch layers;
- the manifest reader.

What it does differently: one lifecycle transition at a time, a context per activation that
refuses everything once that activation ends, and every plugin step bounded. With those rules
the upstream race classes (#96, #176, #91, #127, #185, #194, #218) cannot occur; each has a
regression test in `packages/kernel/test/lifecycle.test.ts`.

The facade exports Guanxi's own surface (`PluginContext`, `GuanxiPlugin`, `PluginHandle`,
`Kernel`, `NodeKernel`), not Cordis's `Context`/`Service`. The governor, Ollama adapter and
sidebar slot wiring behave as before.

The history keeps the Cordis spike (`25bfbd3`..`020ee10`) for the record; nothing from it ships.

## Residual risk

- **Plugin API surface (architecture review M4, partial; blocks the P1 API freeze).**
  - Done:
    - plugins cannot reach the slot registry (`slots` is reserved);
    - every load path re-checks the manifest;
    - `Kernel` and `NodeKernel` are frozen method-only facades.
  - Not done:
    - splitting the plugin-facing entry (types, `definePlugin`, helpers) from the host API;
    - a host facade for `SlotRegistry`;
    - a narrower `KernelCounters` and `PluginState`.

  Do it before `@guanxi/plugin-api` is frozen (ADR-0022 §8).
- **One queue per kernel.** A slow `apply` delays other loads until its 10 s step bound. An
  `apply` that awaits another plugin or a lifecycle call deadlocks until that bound, then fails;
  this is documented as a rule. Revisit per-subtree queues before P1 loads many plugins.
- **Abandoned steps.** An abandoned apply or cleanup may keep running plugin code in the
  background. The kernel refuses its registrations, but cannot stop side effects outside the
  kernel.
- **Pinned legacy rows.** The legacy server's governor and Ollama rows cannot reload until their
  consumers are plugins (K2/K3).
- **Ollama adapter on older Node.** The adapter combines a long-lived lifetime signal with
  `AbortSignal.any` per request. It was measured leak-free on Node 26.9 only, while `engines`
  allows Node ≥ 22.5.
- **Web slot (dev only and mobile).**
  - Editing `runtime.ts` itself shows the list empty once and moves focus (dev only).
  - The slot is hidden below the `md` breakpoint, so it has no mobile surface.
  - Plugin-supplied `href` values are not validated; that is needed before T1 web plugins.
- **Server shutdown.** The HTTP listener close is not bounded; each kernel step is.
