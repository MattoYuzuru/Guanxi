## Implementation and compatibility

Details: [native-agent README](../../../packages/server/src/native-agent/README.md).

- Linux uses sandbox-runtime's bubblewrap filesystem/network profile, requiring
  `--unshare-pid`, `--die-with-parent` and a fresh `/proc`. The wrapper explicitly execs
  bubblewrap, retaining the worker as its parent. Missing/degraded dependencies fail closed.
  Only the packaged seccomp helper, exact proxy sockets and public CA receive extra read
  grants. A workload-only BPF filter installed by util-linux `setpriv --seccomp-filter` denies
  local binding after trusted proxy bridges start; x64/arm64 ABIs are checked.
- macOS arbitrary shell uses one local Linux container per command: `--rm --init`, read-only
  image, `--network none`, selected bind roots and scratch. A framed stdio bridge reaches only
  the sandbox-runtime method/domain proxy. The trusted runner uses UID 0 with only SETUID/GID;
  the workload uses the nonzero host UID/GID with cleared capabilities and no new privileges.
  Write opens of the runner's stdout descriptor and process memory are directly denied. Its
  seccomp guard denies Unix sockets and local binding. Protected ancestors are pinned; nested
  roots cannot reopen read-only protected directories. An absent protected path conservatively makes its nearest
  existing parent read-only. The whole home directory is never mounted. No dedicated
  Docker-socket mount is added; selected roots may contain sockets, whose Unix-socket
  connections are denied. H1's interface/non-loopback fixture, not this host socket observation,
  proves the macOS network namespace boundary.
- Provision the local image with
  `DOCKER_CONTEXT=colima sh packages/server/scripts/prepare-native-execution.sh`.
  Its Node 26 Debian slim base is digest-pinned; each invocation uses the inspected image ID.
  The Docker CLI is resolved/canonicalized once at node boot. Both fixed and arbitrary
  invocations refuse writable trees containing its replacement points. Trusted host
  Node/dependency/helper deny-write grants reach both backends, including nested root cases.
  Colima must share selected roots and node data. Commas in mount paths are refused. Missing
  runtime/image disables arbitrary shell with a localized reason. Fixed absolute
  pwd/ls/cat/head/tail/wc retain their safe fast path. Windows refuses.
- Stop has a one-second worker grace and a five-second parent removal/inspection deadline.
  Unconfirmed cleanup fails the session with `cleanup_unconfirmed`; a private root quarantine
  persists across unload/restart and blocks overlapping sessions/continuations. Interrupted
  create also retains quarantine without an explicit creation acknowledgement. No timeout
  grants a second writer. Recovery is manual after verifying/removing the named container.
- Read-only roots are read-only, scratch writable, and egress permits only GET/HEAD/OPTIONS.
  Full access permits root writes and allowlisted methods. Zero roots means scratch-only host
  writes. Attachments remain immutable. Standard OS executable/library/device exceptions
  remain; no unrestricted host filesystem or network fallback is present.
- Every tool result is scrubbed and bounded to 64 KiB. Large state/query results become
  private session-scoped SHA-256 artifacts with an excerpt, byte count and `tool_output_read`
  continuation. Pages contain at most 8 KiB of UTF-8 content, including JSON-escaping headroom.
  Artifacts are scrubbed before paging, including values registered after storage. Command
  stdout/stderr retain their explicit combined 64 KiB truncation policy; discarded command
  tails are not recoverable artifacts. Decoding preserves split UTF-8 and bounds invalid-byte
  expansion. No new cap is imposed on model context or user inputs.
- Existing pi-agent-core/K3 dispatch, project-root sidecar schema v1, K2 event projection,
  immutable policy, explicit continuation, light plan/queue/notes, attachments and JSON CLI
  remain. No K4 shared SQLite migration was added. R1 owns 30/31; future K4 migrations must be
  32 or higher. This development API still requires recreating sessions from earlier K4
  development policies; no deployed policy migration is claimed.
