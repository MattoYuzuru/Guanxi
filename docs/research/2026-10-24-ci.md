# Parallel CI research and implementation evidence

**Status:** implemented; revision-specific hosted results live in the [PR checks](https://github.com/MattoYuzuru/Guanxi/pull/1/checks) and candidate artifact · **Date:** 2026-10-24

## Observed cost and behavior

The read-only audit found 1,620 retained Guanxi `agent-dev` receipts, including 681 exact
standard full-command hashes across 20–23 October. Full test commands (279 runs) accumulated
1,258.6 wall minutes; web browser 418.9, catalog browser 123.4 and builds 6.7. Summed times
are not CPU time, billing or unique defects. The latest sampled root test took 13.24 minutes:
UI gate self-tests 365.6 seconds, core 293.6. Caching a four-second production build would
not address the dominant cost. Repeated full suites and gate self-scans are the larger costs.

A bounded metadata-only scan of 154 Claude main/subagent transcripts deduplicated Bash tool
IDs and counted command calls, not successful operations: 375 calls containing `git commit`,
85 `git push`, 112 `git clone`, 109 `npm ci`, 318 shared-heavy invocations, 1,578 `tail` and
485 `sleep` calls. Dates in this sample are UTC, 19–23 October. Commands can contain several
operations, so counts are neither a precise push cadence nor success totals. No reasoning,
credentials, raw transcripts or private command contents were exported. The evidence supports
checkpoint-based commits, lead-owned publication, reuse of installations and process-owned
CI waiting; it does not support forcing additional commits/pushes per edit.
The current user-level Claude settings contain one PreToolUse hook and no hook command
mentioning heavy/full gates, npm test or npm ci; no project settings hook was present.
The inspected global Claude memory routes workstation work and does not mandate full gates.

At implementation start local main was `4644f353`; remote main was `b3197d34`. The first CI
PR therefore also tests the owner's pre-existing locally integrated work. This migration does
not claim authorship of those feature changes. Existing lane snapshots are recorded locally;
one redesign fix clone had 15 dirty files, and is preserved without pulling or recloning.

These are applied recommendations, not copied third-party implementation. No external agent
SDK or proprietary runtime is bundled. No new dependency or remote artifact cache service is
needed. Dependency downloads/layers avoid constant source-key misses; test/build output
reuse is deliberately deferred until there is a measured need and complete input identity.

## Implemented coverage and cache boundaries

The [protocol](../operations/ci.md) and [task registry](../../scripts/ci/tasks.mjs) define the
current envelope. Full history is required for signed UI approval lineage. Core shards retain
the ambient-key-file import guard and preserve literal Node test arguments. Linux jobs
prepare user namespaces, dependencies and the labelled native image; macOS runs the actual
Swift helper tests without claiming owner keychain/Touch ID validation. Catalog artifacts
use a mounted ignored path so failure diffs survive container cleanup.

Unknown workspace layout, added packages and unclassified test/build entrypoints fail the
inventory check. Future plugin/native/build additions require explicit platform, dependency,
cache and task classification; a hardcoded current matrix is never evidence that an unknown
future build is covered. Ordinary workspace typechecks remain discovered by npm. New
build outputs are not silently restored from incomplete cross-run cache keys.

## Independent review and fixes

A separate read-only reviewer inspected the implementation and platform assumptions. Six
actionable findings were fixed in a separate author commit `1d6d95d9`:

1. Ubuntu 24.04 lacks `setpriv --seccomp-filter`; the initial 26.04 attempt solved userspace
   but exposed the upstream capability/userns issue below. The revised profile builds pinned
   util-linux 2.41.3 on 24.04 and validates the actual sandbox, not only tool availability.
2. Partial reruns need the successful plan's same-run candidate artifact; use a stable name.
3. Root workspace-layout changes must fail discovery rather than omit future plugins.
4. CLI local guidance must typecheck CLI, not only server.
5. UI local guidance must typecheck UI; transpilation is not typechecking.
6. Catalog failure artifacts must survive host tmp paths and `docker --rm`.

## Remaining scope

The full hosted run and final documentation review are mandatory completion conditions. Existing
product-stage/live/hardware residuals remain; caching does not close them. Gate self-test
per-file caching and cross-run build/task-result caching are follow-ups requiring separate
correctness and timing evidence. No automatic baseline updates, assertion weakening, paid
model tests, self-hosted owner runner or removal of independent review is part of this slice.

## First full hosted observation and portability fixes

[40074271374](https://github.com/MattoYuzuru/Guanxi/actions/runs/40074271374) ran the actual
matrix: quality, production build, Storybook, both web browser shards and gate self-tests
passed; core native, bench units, catalog and one macOS policy probe failed. These are
recorded failures, not a completed gate. The second candidate must verify all fixes.

- The bench launcher closed fd 5/6 after Node reused those numbers for internal event-loop
  pipes. A content-free Linux probe established SIGABRT, not a guessed scheduling delay.
  The supervisor already maps those client stdio slots to ignore; remove unsafe JS closes.
  The fixture now checks actual inherited parent control identities across every client fd
  on Linux; Node-internal FIFOs are not misclassified as parent capabilities. macOS retains
  positional socket checks, not a claimed all-fd identity proof.
- Separately, a new regression closes request input before bounded client finalization and
  asserts the real zero/nonzero exit. It failed before the fix on Mac. Only natural EOF now
  permits exit/status settlement within the existing kill grace; abort/error cleanup stays
  immediate and no success is inferred from EOF. Four targeted Linux cases pass at
  `check-y97mmr8p`; the complete Mac bench module passes at `check-2gwrzmcv`. Both are observed
  local evidence, not reusable source certificates (inherited external skill symlink).
- Native Linux fails inside the pinned dependency's seccomp helper despite successful tool
  probes: `/proc/self/setgroups` capability denial. This matches
  [the upstream report](https://github.com/anthropics/sandbox-runtime/issues/498). A real
  synthetic sandbox preflight now fails early with diagnostic metadata before broad suites.
  No network/filesystem isolation is disabled and node_modules is not patched.
- Exact visual baselines were generated on the Mac's ARM Docker image. Hosted x64 produced
  rounding differences; use an ARM hosted catalog job with the same image digest. Create its
  artifact parent as the host user before the root container runs, preserving host G14–G16
  writes. Never regenerate baseline images to hide a platform mismatch.
- The macOS helper policy probe returned null exit status with no stderr; its assertion now
  reports signal/error metadata before assigning a GUI/hardware cause. It still requires the
  real shared production policy builders to succeed.

The native tool cache contains only the checksummed-source standalone setpriv binary,
keyed by Ubuntu ABI, architecture and the full preparation script (including version/hash/
flags). Code/docs edits keep it reusable; tool/platform changes invalidate it intentionally.
The tool is installed only on ephemeral hosted runners, never bundled with Guanxi. Its
upstream source is [util-linux 2.41.3](https://www.kernel.org/pub/linux/utils/util-linux/v2.41/).

The second full run [40075718742](https://github.com/MattoYuzuru/Guanxi/actions/runs/40075718742)
passed all native setup probes, two core shards, units, all browser/catalog gates and builds.
Two required failures remained: one Linux foreign-replacement fixture and the macOS policy
probe (now identified as SIGSEGV). A CI-only bounded LLDB replay of that synthetic test
request captures its native stack; it does not turn a crash into a pass.

Linux reproduced the download fixture failure at `check-_y6m2fhr`: unlink/recreate immediately
reused dev/inode on ext4. The corrected fixture creates a distinct foreign inode while the
original exists, asserts that identity and atomically replaces the path; refusal and foreign
content preservation remain asserted. Independent review confirmed the sole production
discard caller holds its fully verified descriptor open through cleanup, preventing inode
reuse there. Standalone discard does not prove protection against inode reuse or hostile
concurrent path mutation; future callers must preserve that lifetime boundary rather than
reuse a broad ownership claim. No indefinite per-artifact descriptors or large-file rehash
were added just to make a fixture green.
The two complete affected download/import files pass **0 new / 33 existing**, zero skips,
in the isolated Linux image at `check-w08p2v4s`; the changed fixture is not a new test.

The reviewer also found that an existing indirectly covered script could gain an omitted
step without changing its name. Supported bodies now fail on drift until their actual job
coverage is reconciled; mutation assertions cover each such entrypoint.

Observed second-run timing was 9m52s including scheduling, setup and the failed probes.
The twelve matrix tasks were capped at eight: catalog waited 3m12s before starting and then
took 6m17s. Raise the isolated-runner cap to twelve to remove that self-imposed queue; actual
GitHub account capacity still applies. Cached npm installs took 6–28s, production build 10s
and Storybook 8s. Logs confirm npm cache hits and native Docker layers marked CACHED.
The new standalone tool key was cold and saved after successful native jobs. These are
observations of a failed run, not a guarantee for future runtime or a full-pass claim.

The third candidate's LLDB replay located the macOS SIGSEGV in deferred `CFEqual` inside the
test-only policy probe, not in authentication or signing. Capture the same Boolean comparison
at the actual factory call boundary instead of retaining a CF reference until JSON emission.
The probe still calls the real Security API and asserts all policy/context/no-auth properties;
production helper behavior is unchanged. This diagnoses the observed crash location, not a
proven general CoreFoundation ownership defect. The complete three-file local signer envelope
passes at `check-wne3t0pm`; a fresh hosted candidate must confirm the portability fix. Independent
review found no blocker in this change or the unchanged assertion scope.

The follow-up hosted run showed that moving the comparison alone was insufficient: the
same probe returned corrupted captured counts/flags under the image's default compiler.
A scoped diagnostic branch, isolated from the PR workflow, compared the same source:
[40077446530](https://github.com/MattoYuzuru/Guanxi/actions/runs/40077446530).
macOS 15 + Xcode 16.4 / Swift 6.1.2 failed; macOS 15 + Xcode 26.3 / Swift 6.2.4 passed;
macOS 26 + Xcode 26.6 / Swift 6.3.3 passed. The canonical job now selects installed Xcode
26.3 on the same macOS 15, prints its Swift version and fails if it is missing. No OS check,
policy assertion or optimization was removed. This establishes a toolchain-dependent
failure, not its underlying compiler/runtime mechanism. Installed versions were verified
against the [exact runner-image record](https://github.com/actions/runner-images/blob/macos-15-arm64/20260907.0337/images/macos/macos-15-arm64-Readme.md).

Once the canonical workflow is on main, [manual dispatch](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)
accepts one exact task ID for isolated hosted diagnosis. It emits `full: false`, skips the
aggregate and never substitutes for ready-PR completion; a test proves the input cannot
narrow ready PRs. This keeps future platform repairs from relaunching all unrelated jobs.
