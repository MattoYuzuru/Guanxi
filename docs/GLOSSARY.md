# Пользовательский glossary

**Статус:** proposed UI copy, accepted domain meanings  
**Проверено:** 2026-08-02  
**Языки:** English primary, curated Russian

Этот glossary должен быть доступен из Settings и context-help рядом с редкими
терминами. Объяснения предназначены пользователю, а не только разработчику.

## Основные понятия

### Chat / Чат

Сохраняемая беседа с собственной историей и контекстом.

**Пример:** пользователь создаёт Chat и спрашивает, как приготовить сырники.
Позже он хочет узнать, как заменить розетку, и создаёт новый Chat, чтобы новая
тема не смешивалась с рецептом.

Chat может пережить много Jobs. Переход на другой экран не останавливает
выполняющийся Job.

### Quick Run / Быстрый запуск

Одноразовая задача без необходимости вести диалог: расшифровать аудио, распознать
текст на изображении или получить один structured result.

Quick Run использует ту же Job/Artifact архитектуру. Его retention определяется
выбранным режимом, а не отдельной кнопкой Save.

### Project / Проект

Логический контейнер для связанных Chats, files, Recipes, Agent Runs, Artifacts,
MCP, Skills и permissions.

Project имеет название, иконку и цвет. Он может ссылаться на одну или несколько
папок, но сам не обязан быть папкой.

### Recipe / Сценарий

Сохранённый способ выполнить повторяющуюся задачу: какая operation нужна, какую
модель предпочесть, какие параметры, instructions, dictionary и tools включить.

**Пример:** сценарий «Диктовка промпта» использует выбранную STT-модель, русский
словарь и raw transcript без automatic summary.

`Сценарий` — предлагаемая русская UI-метка вместо буквального `Рецепт`.

### Agent Run / Запуск агента

Длительная многошаговая работа агента с планом, tools, checkpoints, approvals и
проверками.

**Пример:** агент читает repository, меняет Kotlin-код, запускает Gradle tests,
сверяется с официальной документацией, проводит review и сохраняет evidence.

### Artifact / Результат

Сохранённый input или output Job: ответ, reasoning, transcript, audio, image,
document, diff, report, checkpoint или file.

В technical views допустим термин `Artifact`; в обычном русском UI предпочтительна
метка `Результат`.

### Job / Задача

Исполняемая единица работы. Chat хранит общение, а Job отвечает за конкретный
запуск модели/tool/pipeline.

Job имеет очередь, phase, progress, cancel и terminal result. Он продолжает
работать независимо от открытой страницы.

## Модели и память

### Installed model / Установленная модель

Model artifact, доступный локальному Ollama. Установленная модель занимает диск,
но не обязательно RAM/VRAM.

### Loaded model / Загруженная модель

Runtime instance, которая сейчас находится в RAM/VRAM и может обслужить Job.
Загруженность сверяется с Ollama, а не выводится из открытого Chat.

### Model weights / Веса модели

Обученные параметры модели. Обычный Chat не «записывается в веса». Выгрузка
модели из RAM/VRAM не стирает её знания и не меняет файл модели.

### Context window / Окно контекста

Ограниченный объём текста/media tokens, который модель получает для конкретного
вызова. История Chat может быть длиннее окна; тогда приложение выбирает,
компактит или суммаризует часть истории по видимой policy.

### Chat history / История

Messages и Artifacts, сохранённые на диске. Они не занимают accelerator memory,
пока не выбраны и не отправлены в следующий model call.

Retention истории экономит disk/privacy, но само по себе не освобождает VRAM.

### KV cache / Кэш контекста

Временное runtime-представление уже обработанного prompt/context. Оно ускоряет
продолжение, но обычно теряется после unload/restart.

Если история сохранена, приложение может заново отправить её и восстановить
смысловой контекст. Это не гарантирует побитно тот же ответ: sampling, runtime и
model version могут дать другой результат.

### Thinking / Reasoning / Рассуждение

Отдельный поток, который thinking-capable model возвращает помимо final answer.
Он показывается отдельно и хранится как diagnostic Artifact ограниченное время.
Отсутствие отдельного channel нельзя изображать как скрытое reasoning.

## Настройки выполнения

### Keep / Хранить

Chat остаётся до явного удаления.

### 7 days / 7 дней

Default для любого нового Chat, в том числе внутри Project. Срок продлевается от
последней активности пользователя. Для бессрочного хранения нужно выбрать
`Keep`. Перед окончательной очисткой применяется Trash/grace policy.

### Session / На сессию

Короткоживущий Chat. После ухода пользователя и завершения активной Job он
попадает в Trash на 24 часа. Reload/reconnect не завершают Session.

### Manual approvals / Подтверждать действия

Agent спрашивает разрешение перед effectful actions согласно policy.

### Auto within policy / Автоматически в разрешённых границах

Agent действует без каждого отдельного вопроса, но только внутри выбранных roots,
commands, network и integrations. Все действия журналируются.

### Skill / Инструкция

Набор правил и workflow, который агент может загрузить в контекст. Skill помогает
решить задачу, но не расширяет permissions самостоятельно.

### MCP connection / MCP-подключение

Настроенный внешний или локальный источник tools/resources. Все MCP выключены по
умолчанию и включаются на Project/Run с видимой policy.
