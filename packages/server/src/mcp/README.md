# MCP client core

**Status:** implemented (P1-c, library only) · **Updated:** 2026-10-23

A minimal MCP client for the server, with a stdio transport, JSON-RPC 2.0 framing,
the `2026-07-28` handshake, tool listing/calls and a per-session tool budget. It has no MCP
SDK dependency and is not wired into the plugin manager, the native agent loop or the UI yet.
P1 remains in progress.

## Security boundary

> **Not sandboxed yet.** The default spawn port runs an MCP server as the current user with
> no filesystem roots and no network allowlist. Do not enable an untrusted server until the
> K4 `sandbox-runtime` wrapper is wired into the transport port.

Every MCP server is T2 ([ADR-0022 §9](../../../../docs/decisions/0022-plugin-trust-tiers-ui-slots-and-design-tokens.md)).
The manager is off unless project policy explicitly sets `mcp.enabled: true`; a disabled
manager starts no process and tool operations reject with `mcp_disabled`.

The default transport:

- requires an absolute executable path and never uses a shell;
- requires an absolute `cwd`;
- passes an explicit environment of `PATH`, `LANG` and the server's `env` map, never the
  whole parent environment;
- discards stderr, which may contain credentials. The client never reads, logs or copies
  stderr into an error or result.

Secret references are not implemented in this slice. Do not put real secret values in a committed
policy or in test fixtures; the future `secret://` resolution belongs to the plugin manager
and vault work.

## API

- `spawnMcpProcess(spec)` is the default `McpSpawn` port. K4 will provide the sandboxed
  replacement with the same `{ stdin, stdout, kill, exited }` shape.
- `McpClient` connects one server: `connect()` performs the handshake, `listTools()` follows
  every page, `callTool(name, args, options)` returns the raw result object, and `close()`
  kills the process and waits for `exited`.
- `McpClientManager` applies `{ mcp: { enabled, servers } }` project policy; an omitted policy
  is off. `start()` is a no-op when disabled; `listTools(serverId)`, `listAllTools()` and
  `callTool(serverId, name, args, options)` reject with `mcp_disabled` before a spawn.
- `toolContext(tools, count, budget)` returns either `{ mode: 'full', tools }` or
  `{ mode: 'search', tools, omitted }`; in search mode `tools` is exactly
  `mcp_search_tools` and `mcp_load_tool`.
- `searchMcpTools(tools, query, limit?)` returns names and one-line summaries;
  `loadMcpTool(tools, name)` returns the full description and input schema.
- `countToolContext(context, count)` is the same injected-counter measurement used by
  `toolContext`, so hosts can assert `countToolContext(...) <= budget`.

Example:

```ts
const manager = new McpClientManager({
  projectPolicy: {
    mcp: {
      enabled: true,
      servers: [{ id: 'docs', command: '/absolute/bin/docs-mcp', cwd: '/absolute/project' }],
    },
  },
})
await manager.start()
const tools = await manager.listAllTools()
const context = toolContext(tools, text => Math.ceil(text.length / 4), 2_000)
const result = await manager.callTool('docs', 'search', { query: 'router' })
await manager.close()
```

## Protocol behaviour

- **Version:** `initialize` sends `protocolVersion: '2026-07-28'`, `capabilities: {}` and
  `clientInfo.name` from the brand module (`PRODUCT_NAME`). A different server version is
  refused with `mcp_version_mismatch` unless it is listed in
  `allowedProtocolVersions`. `notifications/initialized` is sent only after acceptance, then
  `tools/list` and `tools/call` are allowed.
- **Framing:** newline-delimited JSON-RPC 2.0. The per-message cap defaults to 4 MiB and is
  configurable with `maxMessageBytes`. An oversize frame kills the server and fails pending
  requests with `mcp_message_too_large`.
- **Malformed input:** invalid JSON, a non-2.0 envelope, an invalid response or an invalid
  error object is fatal, kills the server and fails pending requests with `mcp_protocol`.
  The client does not echo the raw line, which could contain credentials.
- **Matching:** numeric ids are generated by the client; responses are matched by id, late
  responses after a timeout or abort are ignored, and server notifications are accepted.
  Server-initiated requests receive a JSON-RPC `-32601` response; the client exposes no
  server-request handler in this slice.
- **Timeout and abort:** each request has a timeout (default 30 s). Timeout sends
  `notifications/cancelled` with `{ requestId, reason: 'timeout' }` and rejects
  `mcp_timeout`; abort sends the same notification with `reason: 'aborted'` and rejects
  `mcp_aborted`.
- **Pagination:** `tools/list` follows `nextCursor` for at most `maxToolPages` pages
  (default 100) and fails `mcp_pagination_limit` rather than looping forever.
- **Calls:** `arguments` must be a JSON-serializable object and are validated before the
  request is sent. The result object, including `isError`, is returned without interpretation.
- **Error objects:** a server JSON-RPC error becomes `mcp_rpc_error` with the original
  `rpcCode` and `data`; stderr is never part of that path.

## Residuals

- K4 sandbox wrapper with declared filesystem roots and a network allowlist.
- HTTP/streamable MCP transport through the egress proxy and its allowlist.
- Secret references resolved into the transport environment by the vault/plugin manager.
- Plugin manager integration, install/rollback and per-project enable UI.
- Agent tool registration and UI exposure; this slice exports no server route or plugin.
