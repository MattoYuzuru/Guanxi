# PalettePreview

## Purpose

Lets the owner compare the three palette candidates of the 2026-10-23 redesign (D-201) in the
real primitives, light and dark side by side, before one is approved.

## When to use

- In the catalog, to review or re-review palette candidates.
- When a new candidate is generated by `packages/ui/tokens/palettes/generate.mjs --write`.

## When not to use

- In product screens: the product reads the approved palette from the token pipeline.
- To try a colour by hand: change the generator and regenerate instead.

## Anatomy and variants

Two columns (light, dark). Each shows the chrome tone with a short navigation, a white (or
deep neutral) session pane, primary and secondary buttons, a switch, four status badges, the
four key swatches with hex values and the measured contrast ratios.

## States

porcelain-cobalt, mist-indigo and linen-azure: one story per candidate.

## Accessibility

- The navigation sample is decorative and hidden from assistive technology.
- Real primitives keep their names and keyboard behaviour.
- Ratios are measured against both the chrome and the session surface.

## Content and i18n

Every label is a `ui.palette.*` message key; hex values and ratios are machine values.

## Motion

None.

## Do / Don't

- Do regenerate the candidates file rather than editing it.
- Don't import this component into product features.
